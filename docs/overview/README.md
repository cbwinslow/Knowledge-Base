# Documentation Overview

Use this overview as a map for navigating the reorganized knowledge base. The paths below point to the most common entry points and the purpose of each collection.

## Recommended Starting Points

- **Setup basics**: Review the quick-start and environment materials in [`docs/setup/`](../setup/) to get a working installation and deployment flow.
- **Architecture references**: The implementation rules and technical overviews in [`docs/architecture/`](../architecture/) describe how the platform is assembled and maintained.
- **Knowledge base guides**: Operator-facing instructions live in [`docs/guides/`](../guides/), including CLI usage and improvement plans.
- **Agent resources**: Workflow summaries and prompt packs are grouped under [`docs/agents/`](../agents/).
- **Project dossiers**: Project-specific blueprints sit in [`docs/projects/`](../projects/), separated by initiative (e.g., `ai_blackjack_poker/`, `cloud_curio/`).
- **Resumes and references**: Profile documents now live in [`docs/resumes/`](../resumes/).

## Navigation Helpers

- The legacy dynamic index remains at the repository root as [`TABLE_OF_CONTENTS.md`](../../TABLE_OF_CONTENTS.md); its links now point to the relocated files.
- Supporting metadata generated for documentation tooling is stored in [`docs/metadata/`](../metadata/).
- The broader library in [`documentation/`](../../documentation/) continues to host research notes, examples, and troubleshooting references.

Keep this overview alongside `docs/README.md` when triaging new documents so they can be slotted into the correct collection.
